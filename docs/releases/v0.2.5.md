# wiretap v0.2.5

This release separates desktop registration from project management. Adding a
webhook project no longer creates a replacement client ID or token.

## Highlights

### Add projects without re-registering

Register the desktop identity once:

```sh
wiretap relay \
  --url https://relay.example.com \
  --admin-token YOUR_ADMIN_TOKEN \
  register --name laptop --save
```

Then add as many project paths as that desktop needs using its saved client
credentials:

```sh
wiretap relay --url https://relay.example.com projects add project-a
wiretap relay --url https://relay.example.com projects add project-b
```

The client ID and token remain unchanged. `register --projects ...` still
works for initial setup, but `--projects` is no longer required.

### Manage projects in the GUI

Settings now has a dedicated Projects card. It lists each project separately
and provides Add and Remove actions. Project changes update the saved project
list and restart the tunnel automatically, so no application restart is
needed.

Registration is presented separately as the one-time operation that creates a
desktop identity. The misleading Re-register action is no longer used for
adding projects.

### Authenticated owner API

The relay adds these client-authenticated endpoints:

- `POST /client/projects`
- `DELETE /client/projects/{project}`

They use the same client ID/token HTTP Basic authentication as the tunnel.
Ordinary project management does not require storing or repeatedly entering
the more privileged relay admin token. A client can remove only its own
projects, and adding a project already owned by the same client is idempotent.

## Removing a project

CLI removal requires explicit confirmation:

```sh
wiretap relay --url https://relay.example.com \
  projects remove project-b --force
```

Removing a project releases its public route and deletes that project's queued
history from the relay database. Deliveries already downloaded into the local
desktop database are not removed. The GUI displays the same warning before it
performs the operation.

## Upgrade notes

Upgrade `wiretap-relay` before using the new project Add/Remove operations.
Older relays do not have the `/client/projects` endpoints. Existing relay
databases, registrations, credentials, projects, and webhook history require
no migration or re-registration.

Projects continue to have one owning desktop client. This release does not add
multiple subscribers or per-subscriber delivery cursors.

## Quality

The release includes new tests across the storage layer, relay HTTP handlers,
typed API client, CLI, and GUI bindings. They cover authorization, credential
preservation, optional registration projects, add/remove synchronization,
relay history cleanup, and tunnel restart behavior.
