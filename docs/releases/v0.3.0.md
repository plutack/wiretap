# wiretap v0.3.0

This release replaces one-client project ownership with independent project
subscriptions and expands the relay's administration and retention controls.

## Deliver one project to multiple clients

A relay project can now have multiple subscribed clients. Each subscriber has
its own start point, acknowledgement cursor, pending count, offline catch-up,
and live delivery stream. A slow or disconnected desktop does not advance the
cursor of another subscriber.

Existing relay databases migrate automatically. Every previous project owner
becomes that project's first subscriber, while project paths, queued webhook
bodies, sequence numbers, and acknowledgement state are preserved.

New subscribers receive only future webhooks by default. An administrator can
opt into retained delivery with `--include-history`:

```sh
wiretap relay --url https://relay.example.com --admin-token TOKEN \
  projects subscribe new-project --client-id CLIENT_ID --include-history
```

Removing a project from a desktop now unsubscribes only that client. The relay
project and retained history remain available to other subscribers. Project
deletion remains a separate, explicit administrator operation.

## More relay management

Relay administration now includes:

- add and remove project subscribers;
- show each subscriber's independent cursor and pending count;
- inspect retained webhook metadata in bounded pages;
- replay a retained webhook to every connected subscriber or one selected
  client;
- delete selected webhooks, every webhook through a sequence, or all retained
  webhooks for a project;
- revoke a client without deleting shared projects or their history.

Examples:

```sh
wiretap relay --url https://relay.example.com --admin-token TOKEN \
  projects unsubscribe new-project --client-id CLIENT_ID

wiretap relay --url https://relay.example.com --admin-token TOKEN \
  webhooks replay new-project 42 --client-id CLIENT_ID

wiretap relay --url https://relay.example.com --admin-token TOKEN \
  webhooks delete new-project 40 41 42

wiretap relay --url https://relay.example.com --admin-token TOKEN \
  webhooks delete new-project --through 100
```

## Desktop fixes

Relay project rows now group project actions, current subscribers, and the
add-subscriber workflow more clearly. Custom dropdown menus render outside card
overflow boundaries, so selectors such as Shell and subscriber selection are
no longer clipped by the next section.

## Upgrade notes

Upgrade `wiretap-relay` before using the v0.3.0 clients or management commands.
Back up the relay's persistent volume before the first start; the new relay
runs a transactional schema migration automatically.

`wiretap relay projects remove` no longer accepts `--force`. The command now
unsubscribes the authenticated client and preserves the project and history.
