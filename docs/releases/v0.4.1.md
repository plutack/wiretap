# wiretap v0.4.1

This release fixes traffic that reached the network without passing through
interception: requests that succeeded normally and were never captured.

## Plain HTTP was not intercepted

Interception exports its proxy settings into the shell it spawns. It exported
only the uppercase `HTTP_PROXY`, and curl deliberately refuses that spelling for
`http://` URLs as a protection against header injection. So plain-HTTP requests
from anything other than the bundled curl, git and node shims went straight to
the destination — looked perfectly healthy, and never appeared in the capture
list. HTTPS was unaffected, which made the gap look intermittent rather than
systematic.

Both spellings are now exported, and stopping interception restores whichever
one the shell had before.

## Local services were invisible

`NO_PROXY` excluded every loopback address, not just wiretap's own listeners.
A local webhook receiver or helper API on another port was therefore never
proxied and never captured, which left the local half of a webhook round trip
missing from the history.

Wiretap now excludes only the addresses it actually bound for the session — the
interception proxy and the local control API — taken from the real ports, so
reconfigured or ephemeral ports are handled correctly. Everything else on
loopback, including your own services, is intercepted like any other request.

## The proxy no longer dials itself

Because that exclusion is narrower, a client that ignores `host:port` entries in
`NO_PROXY` could hand the proxy its own address. The proxy now answers those
requests with `508 Loop Detected` instead of forwarding them to itself.

## Upgrading

Restart `wiretap intercept start`, then reopen any attached shells. An existing
session and its attached shells keep the previous environment until they are
restarted.
