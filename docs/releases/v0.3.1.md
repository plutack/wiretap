# wiretap v0.3.1

This release lets multiple terminals share one local traffic interception
session.

## Attach multiple shells

Start interception normally, then attach from any additional terminal:

```sh
# Terminal 1
wiretap intercept start

# Terminal 2, 3, and later
wiretap intercept attach
```

Every attached shell uses the active proxy, local CA, tool shims, transforms,
and capture session. Attach a different supported shell explicitly when
needed:

```sh
wiretap intercept attach --shell fish
wiretap intercept attach --shell powershell
```

Exiting an attached shell leaves the owner running. Exiting the original shell
stops the session and closes its attachments. To keep the proxy independent of
any child shell, run `wiretap intercept start --no-shell` in an owner terminal
and use `wiretap intercept attach` everywhere else.

## Reliability improvements

Wiretap now records the resolved proxy and local API addresses in its runtime
file, verifies the control API before attaching, and remains compatible with
older PID-only runtime files. Configurations that request an ephemeral proxy
port now propagate the actual bound address to shell variables, Git/curl/Node
shims, and session history. First-run interception also creates its config
directory before opening the default SQLite store.
