# wiretap v0.5.1

Structured diagnostics for the relay and client, with file-backed logging that
keeps the terminal dashboard's rendering intact.

## Relay logs you can follow during restarts

The relay now uses Go's standard `log/slog` with structured startup, database,
ingress persistence, tunnel connection/disconnection, ACK, failure, and HTTP
shutdown events. Each HTTP request receives a generated `X-Request-ID` response
header for correlation with its request and tunnel logs.

Container output defaults to JSON on stderr for Docker/Coolify log collection;
direct binary runs default to readable text. Configure `WIRETAP_LOG_FORMAT` and
`WIRETAP_LOG_LEVEL`, or use `-log-format` and `-log-level`. Info shows lifecycle
activity, while debug adds successful request completion, ingress, and ACK detail.

## Client diagnostics without corrupting the TUI

Desktop, TUI, and operational CLI commands write diagnostics to files instead of
stdout/stderr. Coverage includes local store and tunnel lifecycle, relay reconnect
backoff, webhook persistence, replay and composed-request outcomes, scripts,
interception, TLS/upstream failures, and traffic capture persistence.

Script failures and automatic webhook-forwarding messages no longer print into
the TUI's terminal. Default files are command-specific, for example:

- `<config-dir>/logs/wiretap-tui.log`
- `<config-dir>/logs/wiretap-gui.log`
- `<config-dir>/logs/wiretap-intercept-start.log`

```sh
wiretap tui --log-file /tmp/wiretap-tui.log --log-format json --log-level debug
# Run in another terminal:
tail -f /tmp/wiretap-tui.log
```

`WIRETAP_LOG_FILE` also selects a destination. Flags override environment values.
Files use owner-only permissions on Unix and reset at approximately 10 MiB.
Terminal devices, symlinks, and `-` are rejected as diagnostic destinations.

## Privacy and verification

Logs omit payloads, raw URLs/query strings, headers, credential values, and
peer-controlled error/exception text. The shared logger redacts common secret
attribute names as defense in depth. Operational identifiers, sequence/session
numbers, sizes, status codes, and durations may still appear; review logs before
sharing them.

Validation includes the full race-enabled Go suite, Go vet, repeated focused
logging tests, WebSocket privacy and subprocess SIGTERM lifecycle tests,
terminal-output isolation tests, production GUI compilation, and the docs build.

## Upgrade notes

- Restart the relay and clients. Existing databases and tunnel protocol need no
  migration.
- Client operational commands now require a writable diagnostic file. Use a
  separate file for simultaneous processes; bounded logs are not audit archives.
- There is no new desktop log viewer or browser-console capture in this release.
- `http_shutdown_completed` describes existing HTTP cleanup, not full upgraded
  WebSocket draining. Graceful tunnel draining and bounded client shutdown remain
  separate follow-up work.
