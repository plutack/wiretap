# wiretap v0.3.2

This release adds a secure, portable handoff workflow for relay client
credentials without requiring recipients to know the relay admin token.

## Export a client from the GUI

Relay administrators can create a client in **Settings → Relay server** and
download its one-time credentials as a versioned JSON file. The file includes
the WebSocket tunnel URL, client ID, bearer token, and initial project
subscriptions. Creating or downloading it does not replace the administrator's
own desktop identity.

Treat the file like a password: transfer it through a secure channel and delete
it after the recipient imports it.

## Import from the CLI or GUI

Recipients can install the handoff from the command line:

```sh
wiretap config import ./wiretap-client.json
```

They can also choose the file from **Settings → Relay connection → Import
client credentials**. Wiretap prefers the operating-system keyring for the
imported token and retains the protected mode-`0600` file fallback for
headless systems.

Replacing a different configured identity requires explicit confirmation in
the GUI or `--force` on the CLI. Re-importing the same identity is safe.

## No application restart

A GUI import reloads the relay configuration and replaces only the background
WebSocket tunnel. The desktop window, local SQLite store, interception proxy,
active interception sessions, and captured history remain running. The tunnel's
existing reconnect loop continues to handle ordinary network interruptions.
